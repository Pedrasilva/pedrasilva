# Agent rules

- Module-specific rules live in that module's AGENTS.md: src/lib/marketing/AGENTS.md (captures, intake, profiles, enrichment, posts, nudges, deletion), src/lib/reports/AGENTS.md, src/lib/finance/AGENTS.md (document intake), src/lib/hr/AGENTS.md (leave changes), src/lib/projects/AGENTS.md (timesheet assistant, calendar). Why: keeps the root file small; read the module file before changing that module.
- Pursuit hours (src/lib/projects/use-pursuit.ts): time on a CRM lead is entry_type 'internal', internal_category "Pursuit" + pm_time_entries.opportunity_id (trigger pm_time_entry_pursuit_guard enforces the pairing and blocks new hours on won/lost leads); everyone reads lead names only through crm_leads_directory(), and project-side totals only through pm_project_pursuit_totals (project-financials gate). Why: crm_opportunities stays confidential, and the "Pursuit" name is load-bearing — never rename it.
- Project actual costs use pm_time_entries.cost_rate_snapshot, stamped by DB trigger pm_time_entry_cost_snapshot_trg from pm_cost_rate_periods (built in src/lib/projects/cost-rates.server.ts with the default-rates formula); client values are ignored, and only pm_recalc_cost_snapshots (admin) or backfill change them in bulk. Read actuals through lockedCostRate(snapshot, fallback); forecasts/planning keep current rates. Why: past costs must not change when salaries change.
- Work on holidays/weekends/full-day leave is flagged in pm_time_entries.non_working_day_reason by DB trigger pm_time_entry_nwd_trg (never blocked); such entries are approved one at a time, never in bulk; browser hints come from src/lib/projects/use-non-working-days.ts. Why: the database is the single source for the flag.
- Hours bank (src/lib/hr/use-hours-bank.ts): balance is always the ledger sum; one opening_balance per person (edits audited in pm_hours_bank_audit) and at most one week movement (additional_hours credit or shortfall debit, replaced on re-approval); week movements for weeks ending before the opening "as of" date have no effect; unpaid leave ("Authorized (unpaid)") is shown but never accounted (isUnpaidLeave). Why: history is covered by the opening balance and unpaid leave is time owed.
- New hours only go to stages with status "active" (retainer month stages excepted inside their own month); DB trigger pm_time_entry_active_stage_trg enforces it, picker/assistant/grid filter the same way, and non-active rows show read-only only in weeks that already have hours. Why: closed/planned stages must not collect new time, while existing entries keep saving.
- Automatic non_working timesheet entries follow vacation_requests through DB trigger vacation_request_sync_timesheet_trg (removes old approved range, creates new; skips submitted/approved weeks); the grid shows every non_working entry, flagging ones without an approved source. Why: totals must equal what the grid shows.
- Manual deletions of pm_time_entries done on request are first copied to pm_time_entry_deletion_log (full row JSON, reason, who, when; admin-read only). Why: deleted hours must stay traceable.
- Weekly timesheet workflow notifications come from DB trigger pm_week_workflow_notify (bell) to recipients from pm_week_approver_ids (team approvers covering the person, else "All"-scope approvers, else admins; never the person); the browser then calls sendWeekWorkflowEmails to email those same notifications to people with email notifications on. Change requests live on pm_timesheet_weeks.change_requested_* and are cleared by any status change; self-approval is blocked in DB (pm_timesheet_week_meta) unless nobody else approves, and flagged self_approved. Why: one source for who approves, and the bell and email never disagree.
- Timesheet cells hold several pm_time_entries ("activities"), each with its own hours/note/source/approval; never merge them. Typed edits, assistant drafts and calendar events each create their own entry (calendar ids on that entry); non_working stays one entry per day (unique index). Cell UI lives in src/components/projects/timesheet-activity-cell.tsx. Why: each activity must keep its own description and approval.
- Calendar events become timesheet activities only through CalendarNoteConfirm (src/components/projects/calendar-note-confirm.tsx): the "time · title" description is prefilled, editable, and saved only as the person confirms it. Why: event details reach the timesheet only with the person's explicit consent.
- Voice input goes through src/components/marketing/use-voice-recorder.ts: AudioContext created synchronously in the click, "recording" only after real frames, silent clips never sent, failures (no audio) logged to voice_input_failures (admin-read). Why: Safari/Windows silently recorded nothing before.
- CRM email leads: Gmail threads labelled "CRM" (luis@, GOOGLE_MAIL_API_KEY) become crm_email_lead_drafts via src/routes/api/public/hooks/crm-email-intake.ts (10-min cron, gate token in service-role-only crm_email_intake_gate); only crm_email_lead_confirm (admin) writes contacts/companies/opportunities/activities, and imported threads get "CRM/Importado". Why: nothing enters the CRM without a person confirming.
