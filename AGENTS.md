# Agent rules
- UI translation auditing uses the TypeScript AST checker in scripts/check-i18n.mjs with explicit document/brand exclusions and a signature-count baseline ratchet; never refresh the baseline to admit new UI literals. Why: existing debt remains visible while tests/CI block new untranslated UI without touching document languages.
- Projects route and component UI uses namespace keys for constant maps, interpolated plural counts and locale-aware display formatting; document prose remains outside UI translation. Why: language changes must update route labels without changing stored enums, document language or financial calculations.
- Marketing portfolio uses immutable profile-owned identity and optional live linkage; read src/lib/marketing/AGENTS.md before identity changes. Why: no operational pseudo-projects or lost editorial history.
- Marketing timing computations stay in the Marketing module's shared pure scorer and RLS-scoped data RPC. Why: Calendar and Insights need identical recommendations without accessing unrelated financial records.
- Instagram publication uses persistent database claims and a recorded pre-send boundary; ambiguous provider responses are never resubmitted automatically. Why: overlapping jobs and uncertain network outcomes must not duplicate posts.
- Reel video retention uses Marketing's service-only persistent cleanup claims in the existing private scheduled job; purge evidence is outside approval hashes and media reuse is locked through shared upload advisory locks. Why: storage removal must preserve publication history and never race new drafts.
- Composer shares planner fees, invalidates on billing edits, and normalizes frozen relative dates at render without writes. Why: totals and labels agree.
- Proposal editor display labels live in an editor-only key map; stored block titles/content, print labels and document-language autonyms are independent of UI locale, with exact documented output scopes in the AST allowlist. Why: switching editor language must never rewrite client documents.

- Weekly notes use independent RLS-protected storage and revision-checked saves; week topics are editor-confidential and quote conversion relinks opportunity history in its existing transaction. Why: HR privacy and note autosave must not affect planning or approvals.

- Read projects/finance AGENTS.md, including issued-PDF rules. Why: preserve actuals and fiscal guards.
- Issued PDF draft saves use the queue's existing created_expense_id relationship and a dedicated invoker transaction; reopening reads that link before editing/confirming. Why: RPC-only queue identifiers must never leak into document inserts, and extraction/entity/evidence must survive deferred completion.

- Every migration creating a public table must explicitly revoke TRUNCATE from anon and authenticated on that table, preserving all other privileges; leave platform-owned supabase_admin defaults unchanged and verify postgres public-table defaults plus all existing public-table grants. Why: new tables must remain protected regardless of their creator.
- Read module AGENTS.md before edits: src/lib/{marketing,reports,finance,hr,projects,crm}. Why: module rules stay local.
- Marketing approvals use the module's advisory-warning and hash-bound confirmation rules. Why: editorial approval must not be gated by readiness while content and publication evidence stay protected.
- Project-financial SELECT requires PSA staff and scoped financial permission, with administrator oversight; non-admin tax history is scoped to authorized companies/documents. Why: entity isolation must hold in database reads, not only navigation.
- Retainer actuals use retainerCostRate; missing costs suppress totals/margins. Why: missing snapshots must not imply free labour.
- Inventory controls use useInventoryEditAccess mirroring can_manage_inventory. Why: view permission is not edit permission.
- Pursuit hours: internal + "Pursuit" + opportunity_id; pm_time_entry_pursuit_guard blocks new hours only on lost deals. All picker/voice choices use crm_leads_directory.can_log_hours through pursuitChoices; calendar suggestions/report retain is_open. Project totals reuse pm_project_pursuit_totals and pm_projects.opportunity_id. Why: protects CRM and preserves costs.
- Project actual costs use pm_time_entries.cost_rate_snapshot, stamped by DB trigger pm_time_entry_cost_snapshot_trg from pm_cost_rate_periods (built in src/lib/projects/cost-rates.server.ts with the default-rates formula); client values are ignored, and only pm_recalc_cost_snapshots (admin) or backfill change them in bulk. Read actuals through lockedCostRate(snapshot, fallback); forecasts/planning keep current rates. Why: past costs must not change when salaries change.
- Work on holidays/weekends/full-day leave is flagged in pm_time_entries.non_working_day_reason by DB trigger pm_time_entry_nwd_trg (never blocked); such entries are approved one at a time, never in bulk; browser hints come from src/lib/projects/use-non-working-days.ts. Why: the database is the single source for the flag.
- New hours only go to stages with status "active" (retainer month stages excepted inside their own month); DB trigger pm_time_entry_active_stage_trg enforces it, picker/assistant/grid filter the same way, and non-active rows show read-only only in weeks that already have hours. Why: closed/planned stages must not collect new time, while existing entries keep saving.
- Automatic non_working timesheet entries follow vacation_requests through DB trigger vacation_request_sync_timesheet_trg (removes old approved range, creates new; skips submitted/approved weeks); the grid shows every non_working entry, flagging ones without an approved source. Why: totals must equal what the grid shows.
- Manual deletions of pm_time_entries done on request are first copied to pm_time_entry_deletion_log (full row JSON, reason, who, when; admin-read only). Why: deleted hours must stay traceable.
- Weekly timesheet workflow notifications come from DB trigger pm_week_workflow_notify (bell) to recipients from pm_week_approver_ids (team approvers covering the person, else "All"-scope approvers, else admins; never the person); the browser then calls sendWeekWorkflowEmails to email those same notifications to people with email notifications on. Change requests live on pm_timesheet_weeks.change_requested_* and are cleared by any status change; self-approval is blocked in DB (pm_timesheet_week_meta) unless nobody else approves, and flagged self_approved. Why: one source for who approves, and the bell and email never disagree.
- Phone capture lives at /m (src/routes/m*.tsx), a sibling of _app with its own guard; reuses NoteComposer variant="quick", TimesheetAssistantSheet and listMyPendingNudges; there is a manifest but no service worker. Why: phone flows must not change desktop behaviour or preview caching.
- Homepage weekly planning derives only the caller's personal approved allocation slots from weekBoardQuery, never draft_slots; navigation exposes the weekly board to PSA staff without widening Projects module access. Why: private drafts, existing project permissions and no-rates projection must stay intact.

- Unlinked quotes default relative; pm_relative_normalize_dates keeps weekdays, <2010 prints weeks. Why: unchanged hours/fees.
- Quote revisions lock root, retain source number and print stored revision minus one; unique number/revision. Why: new work alone consumes annual numbers.

- Project financial views share financial-calculation.ts for exact working-calendar plans, author-based saved-entry valuation, incomplete-cost propagation and unrounded value-minus-cost profit; accounting retains canonical fiscal signs and cash scope, quotes keep NO_HOLIDAYS and retainers never estimate missing actual costs. Why: identical economic scopes must reconcile without changing historical records.

- CRM and Product UI translates display labels at render and uses separate locale-aware money wrappers; client datasheet/schedule output keeps its original formatters and stored values. Why: UI language must not change documents, enums or prices.
