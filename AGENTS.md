# Agent rules

- Module-specific rules live in that module's AGENTS.md: src/lib/marketing/AGENTS.md (captures, intake, profiles, enrichment, posts, nudges, deletion) and src/lib/reports/AGENTS.md. Why: keeps the root file small; read the module file before changing that module.
- Timesheet assistant (src/lib/projects/timesheet-assistant.functions.ts) only drafts entries for the signed-in user; saving happens in the browser through useUpsertTimesheetCell/useEnsureStageRow with source "assistant". Why: rate snapshots and triggers apply exactly as for typed hours.
- Google Calendar suggestions (src/lib/projects/calendar.server.ts) always run for the caller's own user id; refresh tokens are AES-GCM encrypted with CALENDAR_TOKEN_KEY in user_calendar_connections (service-role only), event data is never stored, saved events are tracked in pm_time_entries.calendar_event_ids. Why: per-person privacy; external_id is single-valued and reserved for imports.
- Pursuit hours (src/lib/projects/use-pursuit.ts): time on a CRM lead is entry_type 'internal', internal_category "Pursuit" + pm_time_entries.opportunity_id (trigger pm_time_entry_pursuit_guard enforces the pairing and blocks new hours on won/lost leads); everyone reads lead names only through crm_leads_directory(), and project-side totals only through pm_project_pursuit_totals (project-financials gate). Why: crm_opportunities stays confidential, and the "Pursuit" name is load-bearing — never rename it.
- Project actual costs use pm_time_entries.cost_rate_snapshot, stamped by DB trigger pm_time_entry_cost_snapshot_trg from pm_cost_rate_periods (built in src/lib/projects/cost-rates.server.ts with the default-rates formula); client values are ignored, and only pm_recalc_cost_snapshots (admin) or backfill change them in bulk. Read actuals through lockedCostRate(snapshot, fallback); forecasts/planning keep current rates. Why: past costs must not change when salaries change.
- Work on holidays/weekends/full-day leave is flagged in pm_time_entries.non_working_day_reason by DB trigger pm_time_entry_nwd_trg (never blocked); such entries are approved one at a time, never in bulk; browser hints come from src/lib/projects/use-non-working-days.ts. Why: the database is the single source for the flag.
- Hours bank (src/lib/hr/use-hours-bank.ts): balance is always the ledger sum; one opening_balance per person (edits audited in pm_hours_bank_audit) and at most one week movement (additional_hours credit or shortfall debit, replaced on re-approval); week movements for weeks ending before the opening "as of" date have no effect; unpaid leave ("Authorized (unpaid)") is shown but never accounted (isUnpaidLeave). Why: history is covered by the opening balance and unpaid leave is time owed.
- New hours only go to stages with status "active" (retainer month stages excepted inside their own month); DB trigger pm_time_entry_active_stage_trg enforces it, picker/assistant/grid filter the same way, and non-active rows show read-only only in weeks that already have hours. Why: closed/planned stages must not collect new time, while existing entries keep saving.
- Automatic non_working timesheet entries follow vacation_requests through DB trigger vacation_request_sync_timesheet_trg (removes old approved range, creates new; skips submitted/approved weeks); the grid shows every non_working entry, flagging ones without an approved source. Why: totals must equal what the grid shows.
