# Projects module rules

- Cost-period rebuilds use pm_replace_cost_periods for atomic replacement and queue acknowledgement; admin and scheduled paths share an advisory lock and revision check. Why: failed or stale concurrent runs must preserve periods and pending work.
- Authorized internal Backoffice snapshots use pm_backoffice_salary_cost and overhead_salary without modifying cost periods or the Projecto overhead pool; reporting displays them as overhead analysis and excludes them from overhead-loaded business totals. Why: the same salary must not be counted twice.
- Retainer actuals use only saved positive snapshots for task/direct/detail paths, independently of shared budget estimates. Why: missing costs must suppress totals and margins, not become team-rate estimates.

- Weekly planning uses pm_week_board's explicit no-rates projection; week-board.ts owns half-day inference and PLAN_UTILISATION. Stage 2 saves only protected drafts through atomic pm_week_draft, merging changed slots under a row lock; never mutate allocations, stage dates or timesheets. Why: draft planning and actuals remain separate and staff cannot access drafts or financial data.
- Weekly draft stage labels use the complete per-project stage_tree for WBS numbering, while stage choices use only eligible leaves; undo/redo applies stroke deltas instead of replacing the whole week. Why: numbering matches Gantt and other planners' unrelated edits survive undo.
- Weekly slots touch their parent audit timestamp through database triggers; approved rows require the transaction-local apply guard, and validated notes are planner-private. Resolve ambiguous strokes per covered day and derive omitted Gantt bookings from live allocations, without new storage. Why: direct writes cannot bypass safeguards and reload preserves review evidence.

- Timesheet assistant (src/lib/projects/timesheet-assistant.functions.ts) only drafts entries for the signed-in user; saving happens in the browser through useUpsertTimesheetCell/useEnsureStageRow with source "assistant". Why: rate snapshots and triggers apply exactly as for typed hours.
- Google Calendar suggestions (src/lib/projects/calendar.server.ts) always run for the caller's own user id; refresh tokens are AES-GCM encrypted with CALENDAR_TOKEN_KEY in user_calendar_connections (service-role only), event data is never stored, saved events are tracked in pm_time_entries.calendar_event_ids. Why: per-person privacy; external_id is single-valued and reserved for imports.
- Project expenses (pm_expenses): approval is optional (approval_state, default not_required); team members on the project submit and see only their own rows plus ones sent to them; approval/invoicing columns and approved/paid status change only via pm_expense_request_approval / pm_expense_decide_approval or by admins / projects.view_financials (guard trigger pm_expenses_guard); "Por faturar" = isReadyToInvoice (mirrors idx_pm_expenses_ready_to_invoice). Why: most expenses need no approval, but financial data stays confidential.

- Weekly publication uses pm_preview_week_plan/pm_apply_week_plan with revision tokens, a transaction-local apply guard, serialized writes and transactional bells; pm_week_publications retains prior approvals. Planning removals retire allocations with planning_removed_at, and planning-only consumers filter them while actual/task joins retain them. Why: approval cannot partially apply or cascade-delete historical hours.

- Timesheet cells hold several pm_time_entries ("activities"), each with its own hours/note/source/approval; never merge them. Typed edits, assistant drafts and calendar events each create their own entry (calendar ids on that entry); non_working stays one entry per day (unique index). Cell UI lives in src/components/projects/timesheet-activity-cell.tsx. Why: each activity must keep its own description and approval.
- Calendar events become timesheet activities only through CalendarNoteConfirm (src/components/projects/calendar-note-confirm.tsx): the "time · title" description is prefilled, editable, and saved only as the person confirms it. Why: event details reach the timesheet only with the person's explicit consent.
- Gantt uses schedule-engine and atomic pm_gantt_save with scope/revision/overlap guards; relative conversion is preview-bound and transactional. Quote summaries sum quoteLeafFee leaves with source overrides/multiplier, never stale parent budgets. Why: dates and fees must agree without partial saves.
- Office calendar: office closures are expanded into holidays rows (tipo fecho_atelier, office_closure_id) and per-day approved férias (vacation_requests.office_closure_id), only through pm_office_calendar_plan/pm_office_calendar_apply (token, admin); live projects re-schedule only via the confirm dialog using reflowForCalendar. Why: every consumer already reads holidays, and leave/plan changes must be previewed, never silent.
