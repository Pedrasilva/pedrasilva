
- Finance intake queue statuses: filing a bank/"other" document sets "filed", confirming a payment match sets "paid"; "approved" is only for purchase approvals. Multi-document PDFs become one queue item per document sharing the source file (split_of_file_url + page range) and each is read with a page-only instruction (pdf-lib can't parse many bank PDFs). Claude reads first; Gemini is a second reader only for SECOND_READER_TYPES. Why: clear status semantics and lower AI cost.
- Email intake reads only the Google connection signed in as the address in finance_intake_settings (findMailboxKey in gmail-intake.ts; no connection → 503, never another mailbox), query "has:attachment newer_than:14d"; finance_sender_rules (address or domain) run before any AI read — ignore wins, process forces AI "ignored" into triage. Why: docs@ is a dedicated finance mailbox; personal inboxes are never read for finance.
- Duplicates (src/lib/finance/intake-duplicates.server.ts) run before any AI read: same file SHA-256 → status "duplicate" without a model call; then NIF+normalised number+year, bank account/date/amount/ref or statement period; probable matches block approval until resolved, decisions kept per ordered pair in finance_duplicate_decisions. Why: nothing is ever created twice and a person decides unclear cases once.
- Learning (src/lib/finance/intake-learning.server.ts): active finance_intake_instructions go to Claude as "Regras do estúdio", supplier defaults come from the last 2+ agreeing approved items, up to 5 finance_intake_corrections as examples; what was applied is stored on the queue row (applied_learning). Why: rules beat model judgement and every document shows why.
- Suspected duplicate purchases (src/lib/finance/purchase-duplicates.functions.ts, admin + finance): same supplier + normalised number + year, or same supplier + total ±0.01 + date ±5 days without a number match; voiding sets status cancelled with void_reason/voided_duplicate_of/voided_by/voided_at (never deleted), 'not duplicate' is stored per pair in finance_duplicate_decisions. Why: duplicates must stay traceable and decisions remembered.
- Recipient check (src/lib/finance/other-entities.server.ts) runs on every read after type/direction: a recipient NIF that is set and not PSA's (company settings), on a document PSA did not issue, becomes intake_type "outra_entidade" / route "other_entity" (never a purchase or bank document); finance_other_entities (by NIF) decides archive → filed, ignore → route ignored, forward → emailed download link then filed; recipient NIF model disagreement routes to triage. A person's forced type wins. Why: mail for related companies arrives at docs@ and must never enter PSA's books.
- Notes ("Guardar nota") are saved as finance_intake_instructions with scope document / recipient_nif / supplier_nif / sender / global, the document is re-read at once, and similar pending items are re-read only after the person confirms the preview. Why: rules act immediately but never silently on other documents.
