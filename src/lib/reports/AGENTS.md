# Reports module rules

- Reports module: calculations are pure functions in src/lib/reports/* (no Supabase inside), data loaded by hooks in the same folder; access via v2 reports.view/all. Why: reports are read-only and their maths is reused across reports.
- Business performance (revenue, cost, profit, utilisation, capacity) is computed only by src/lib/reports/business-performance.ts, used by both the projects dashboard card and the report. Why: both must always show the same numbers.
- Project budget and actual cost come from src/lib/reports/budget-consumption.ts (shared by projects dashboard and budget report): budget = own (quote is_self) stages + positive margin on supplier stages; cost excludes purchases/expenses matched to those stages' suppliers. Why: budgets measure PSA's own work only, one definition everywhere.
- Billable split (billable project / non-billable project / internal, leave excluded) is computed only by src/lib/reports/billable-split.ts, which reuses entryFigures from business-performance.ts. Why: % billable must equal business-performance utilisation.
- Capacity forecast is computed only by src/lib/reports/capacity-forecast.ts: available = computeHoursLogged expected hours; planned = pm_allocations (hours_per_day × working days, else % × daily hours) on is_self active/planned stages; placeholders shown as unassigned. Why: capacity must match Hours logged, and pm_resource_allocations_forecast is not populated.
- Estimate vs actual per phase type is computed only by src/lib/reports/estimate-vs-actual.ts: planned = pm_stages baseline_target_hours/baseline_budget on is_self leaf stages, actual = stageActuals (locked snapshots); phase type from quote phase_code, else F-number/name rules, else parent — unmapped stays unmapped. Why: no guessing, one mapping everywhere.
