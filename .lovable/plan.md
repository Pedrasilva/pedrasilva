# Proposal Versioning & Send-to-Lock

Track every "sent" proposal as an immutable revision (rev 00, 01, 02…) with its PDF stored in Lovable Cloud, and keep an editable working copy alive until the proposal is Won or Lost — at which point the working copy also locks.

## User flow

1. **Compose** — user edits proposal in the composer as today. Top bar shows current rev label (e.g. `Rev 00 — Working`).
2. **Send Proposal** — new primary button next to Download.
   - Confirmation dialog: shows the auto-filename `{title} {YYMMDD} proposal rev NN` (NN = next sent count) and a "Generate PDF now" step.
   - The browser opens the print dialog with the correct filename preset. The user picks *Save as PDF* and returns the file via a file input in the dialog (drag-drop or picker).
   - On upload: the file lands in the `proposal-pdfs` bucket, a snapshot row is written with the full proposal + blocks + rev number + storage path, and the composer refreshes.
3. **Versions panel** — a new sidebar/tab in the composer lists every revision:
   - `Rev 00 · Sent 03 Jul 2026 · locked` → click opens read-only preview + Download PDF.
   - `Rev 01 · Working` → the live editable copy.
4. **Read-only mode** — when a locked snapshot is opened, all edit UI (block library, settings, inline editors, drag handles) is disabled; only Preview / Download / Duplicate-to-new-revision are shown.
5. **Won / Lost** — status change to `accepted` (Won) or `declined` (Lost) also locks the working copy: it becomes read-only, no new revisions can be sent.

## Data model

Reuse the existing `psa_proposal_snapshots` table (already there for auto-history) with two new columns:

- `kind` text — `'auto' | 'sent'` (default `'auto'`, existing rows migrated to `'auto'`).
- `rev_number` int — nullable; set only for `kind='sent'`. Unique per `(proposal_id, rev_number)` when not null.
- `pdf_storage_path` text — nullable; storage object path in `proposal-pdfs`.
- `pdf_filename` text — nullable; display filename.

Plus on `psa_proposals`:

- `locked_at` timestamptz nullable — set when Won/Lost triggers full lock.
- `outcome` text nullable — `'won' | 'lost'` mirrored from status for clarity.

Rev number derivation: `select coalesce(max(rev_number), -1) + 1 from psa_proposal_snapshots where proposal_id = $1 and kind = 'sent'` — computed server-side inside the send server function.

## Storage

New private bucket `proposal-pdfs`. RLS on `storage.objects`:
- SELECT/INSERT restricted to users with `crm.pipeline` permission or admin.
- Path convention: `{proposal_id}/rev-{NN}-{safeFilename}.pdf`.

Downloads use short-lived signed URLs generated by a `getProposalPdfUrl` server fn.

## UI surfaces

- **`composer-top-bar.tsx`** — add `Send Proposal` button; disable editing controls when the currently-viewed snapshot is locked or the proposal has `locked_at`.
- **New `versions-panel.tsx`** — collapsible right-rail listing revisions with status badges, actions (View / Download / Restore as working copy).
- **New `send-proposal-dialog.tsx`** — shows filename preview, triggers `window.print()` with the correct `document.title`, then a file input to upload the resulting PDF; posts to the send server fn.
- **`canvas.tsx` / `block-*`** — a `readOnly` prop threaded through so blocks render as static when viewing a locked snapshot.

## Server functions (`src/lib/psa-proposal/versioning.functions.ts`)

- `sendProposal({ proposalId, pdfBase64, filename })` → validates auth, computes next rev, uploads PDF via `supabaseAdmin` to `proposal-pdfs`, inserts snapshot row with `kind='sent'`, sets `proposal.sent_at` and status to `sent` if still `draft`/`review`.
- `getProposalPdfUrl({ snapshotId })` → returns 5-min signed URL.
- `restoreRevisionToWorking({ snapshotId })` → convenience: overwrites the working blocks with the snapshot's blocks (creates an `auto` safety snapshot first).

## Locking rules (client-enforced + server-guarded)

- Composer sets `readOnly = true` when: viewing a snapshot OR `proposal.locked_at !== null`.
- Server: an `updated_at` trigger on `psa_proposal_blocks` / `psa_proposals` rejects writes if the parent proposal has `locked_at` set.
- Status change to `accepted` or `declined` stamps `locked_at` via a `before update` trigger.

## Order of implementation

1. Migration: bucket, new columns, trigger, storage policies.
2. Server functions.
3. React Query hooks (`useSendProposal`, `useProposalRevisions`, `useProposalPdfUrl`).
4. `SendProposalDialog` + wiring in top bar.
5. `VersionsPanel` + read-only propagation through canvas/blocks.
6. Outcome-locks: badge in top bar, disable inputs.

## Out of scope for this pass

- Email delivery of the PDF (only local storage + link).
- Diff view between revisions.
- Multi-branch (parallel drafts from an old revision) — restore overwrites the single working copy.
